1. アプリ全体の構成とデータの流れ

アプリはFlutterで作られています。画面はFlutterのWidget（ウィジェット）を組み合わせて表示し、利用者が入力した値はデータクラスにまとめられます。授業・課題・出席記録はSharedPreferencesを使って端末内に保存します。

起動：main.dart → 日本語表示の準備 → 授業・課題・出席データの読み込み → MainScreen
画面遷移：MainScreen → ホーム／時間割／課題／メモ／設定
授業：入力画面 → Lesson → LessonData → LessonStorage → 端末保存
課題：入力画面 → Task → TaskData → TaskStorage → 端末保存
出席：授業と日付を組み合わせて状態を記録 → AttendanceStorage → 端末保存

プロジェクト内の主なフォルダー

場所役割
lib/Flutterアプリ本体のDartソースコード。
lib/screens/ホーム、時間割、課題などの画面と、その画面で使うデータ処理。
test/自動テストのソースコード。
android/、ios/、windows/等各OSでアプリを動かすためのFlutterプラットフォーム設定・ネイティブ側の土台。
build/、.dart_tool/ビルドやツール実行時に生成されるファイル。通常、画面機能の編集対象ではありません。

画面とデータの分担

  • Screen / Widget：入力欄、ボタン、一覧など、利用者が見る画面を作ります。
  • State：選択中の日付・タブなど、画面が表示されている間に変化する状態を持ちます。状態変更後に setState を呼ぶと画面が再構築されます。
  • Model（データクラス）：TaskやLessonのように、1件のデータを表します。
  • Storage：データをJSON形式に変換し、端末に保存・読み込みします。

2. 起動・画面切り替え・ホーム画面

lib/main.dart

Flutterアプリの起動点です。日本語ローカライズを設定し、アプリ起動前に保存データを読み込みます。

  • main()：Flutterの初期化を行い、MyAppを起動します。
  • _initializeApp()：日本語の日付表示情報を初期化し、LessonStorage、TaskStorage、AttendanceStorageから端末内データを順に読み込みます。
  • MyApp：MaterialAppを作り、ロケールを日本語（ja_JP）に設定します。
  • _AppStartup / _AppStartupState：FutureBuilderで初期化の完了を待ちます。読み込み中は進行表示、完了後はメイン画面、失敗時はエラー画面を表示します。
  • _StartupErrorScreen：初期化エラーを表示し、再試行ボタンで初期化をやり直せる画面です。

データへの影響：読み込みが完了する前にメイン画面を出さないことで、保存済みデータの復元前に空の一覧が表示されるのを防いでいます。

lib/screens/main_screen.dart

アプリの下部ナビゲーションを管理し、主要画面を切り替える親画面です。

  • MainScreen：利用者名を受け取り、画面全体を構成します。
  • _MainScreenState：_selectedIndexで現在のタブを管理します。IndexedStackを使うため、タブを切り替えても各画面の状態を保持します。

タブは、ホーム、時間割、課題、メモ、設定の5つです。時間割タブはClassScreen、課題タブはAssignmentScreenに接続します。

lib/screens/home_screen.dart

今日の授業、今日が締切の課題、今週の課題の提出進捗、出席率をまとめて見せるダッシュボードです。

  • HomeScreen：画面に挨拶として表示する利用者名を受け取ります。
  • _HomeScreenState：現在日付を取得し、画面に出す授業・課題・出席率を計算してUIを構築します。
  • _HomeLessonDetail：アイコンと説明文字を横並びにする、画面内だけで使う小さな表示Widgetです。
  • _weekday()：曜日番号を「月」から「日」の文字に変換します。

今日の授業：曜日をキーにLessonData.lessonsByDayから授業を取り出し、開始時刻順に並べます。「今週の予定」ボタンからカレンダー画面へ移動します。

今日の締切：課題の締切文字列が今日のYYYY-MM-DDと完全一致し、isDoneがfalseの課題を表示します。日付の書式が違う場合や提出済みの場合は表示対象になりません。

今週の課題：月曜日から翌週月曜日の直前までに締切がある課題を対象にします。DateTime.tryParseで解析できない締切は対象外です。ここでは課題名一覧ではなく、完了件数／全件数と進捗率だけを表示します。提出済みも分母（全件数）に含みます。

出席率：AttendanceStorageから率と回数を取得します。出席欄を押すと出席状況画面に移動し、戻ってきた後にホーム画面を再描画します。

3. 時間割（授業）のファイルとクラス

lib/screens/class/lesson_data.dart

授業1件の構造、曜日別の授業一覧、端末保存をまとめたファイルです。

  • Lesson：授業名（name）、先生（teacher）、教室（room）、表示用時間（time）、並べ替え用開始時刻（startTime）を持ちます。toJson()とfromJson()でJSONとの変換を行います。
  • LessonData：月曜から日曜までをキーにした静的な授業リストを保持します。実行中の画面は同じデータを参照します。
  • LessonStorage：SharedPreferencesのlesson_dataキーにJSONを保存し、起動時に復元します。

startTimeは9:00なら900のような整数で、時刻順ソートに使用します。

lib/screens/class/class_screen.dart

曜日ごとに時間割を表示し、授業の追加・編集・削除を行う画面です。

  • ClassScreen / _ClassScreenState：曜日選択状態を保持し、選択曜日の授業を開始時刻順に表示します。
  • _addLesson()：授業追加画面を開き、戻り値があれば選択曜日のリストへ追加して保存します。
  • _saveLessons()：保存失敗をスナックバーで通知し、再試行手段を表示します。
  • _LessonDetail：授業の時間・教室・先生をアイコン付きで表示する補助Widgetです。

授業カードをタップすると編集画面へ進み、保存後は対象の授業を置き換えます。カードを左へスワイプすると削除します。

lib/screens/class/add_class_screen.dart

新しい授業の名前・先生・教室・時間を入力する画面です。

  • AddClassScreen / _AddClassScreenState：テキスト入力欄と「保存」ボタンを表示します。
  • parseStartTime()：時間帯の先頭時刻を分離し、HHMM相当の整数へ変換します。時間帯の区切りとして複数の波線・ハイフンを扱います。

必須欄が空なら案内を出して保存を止めます。入力値からLessonを作成し、Navigatorの戻り値として時間割画面へ返します。

lib/screens/class/edit_class_screen.dart

登録済み授業を編集する画面です。EditClassScreenは対象のLessonを受け取り、_EditClassScreenStateが入力欄の初期値として各項目を設定します。

保存時は入力値と再計算した開始時刻から新しいLessonを作り、前の画面へ返します。実際のリスト差し替えと端末保存はClassScreen側の役割です。

lib/screens/class_otherscreen.dart

OtherScreenを定義し、現状は「設定」という見出しと「設定画面」という案内を表示します。実際の設定項目はまだ実装されていないプレースホルダー画面です。

4. 課題のファイルとクラス

lib/screens/task/task_data.dart

課題データの型、実行中の一覧、端末保存を担当します。

  • Task：課題名（title）、科目（subject）、締切（deadline）、提出済みか（isDone）を保持します。初期状態ではisDoneはfalseです。
  • Task.toJson() / Task.fromJson()：課題データをJSONへ変換し、保存データから復元します。
  • TaskData：アプリ実行中の課題一覧tasksを保持します。
  • TaskStorage：SharedPreferencesのtask_dataキーを使い、課題一覧を保存・読み込みします。

lib/screens/task/assignment_screen.dart

課題一覧、提出状態の切り替え、課題の編集・削除・追加をまとめた画面です。

  • AssignmentScreen / _AssignmentScreenState：一覧画面と選択中タブを管理します。
  • _getFilteredTasks()：「すべて」「未提出」「提出済み」の条件でTaskData.tasksを絞り込みます。
  • _buildTabButton()：タブボタンを作り、選択状態を更新します。

追加ボタンはAddAssignmentScreenを開き、返された課題を一覧に追加して保存します。チェックボックスで提出状態を変更します。左スワイプで削除し、行をタップすると編集画面へ移動します。

lib/screens/task/add_assignment_screen.dart

課題名・科目名・締切を入力して新しい課題を作成します。

  • AddAssignmentScreen / _AddAssignmentScreenState：入力欄と追加ボタンを管理します。
  • 3項目のいずれかが空の場合はスナックバーで知らせ、追加を中止します。
  • 入力された締切は文字列のままTask.deadlineへ入ります。画面の例は2026-08-09形式です。
  • 作成したTaskをNavigatorの戻り値として一覧画面へ返します。

lib/screens/task/edit_assignument_screen.dart

課題の名前・科目・締切を編集する画面です。ファイル名のassignumentは現状の実ファイル名で、一般的な綴りassignmentとは異なります。

EditAssignmentScreenは編集対象の課題を受け取ります。_EditAssignmentScreenStateはinitState()で既存値を入力欄に設定し、dispose()でTextEditingControllerを解放します。保存すると課題を更新し、保存処理を依頼して、更新された課題を一覧画面に返します。

5. カレンダー予定のファイルとクラス

lib/screens/carender/schedule.dart

カレンダー上の予定1件を表すScheduleクラスを定義します。予定名、開始日、終了日、色を保持し、終了日が開始日より前でないことをassertで確認します。フォルダー名carenderは現在のプロジェクト上の綴りです。

lib/screens/carender/calender_screen.dart

table_calendarを利用して月間カレンダーと選択日の予定一覧を表示します。

  • CalendarScreen / _CalendarScreenState：表示中の月、選択日、予定一覧を管理します。
  • _eventsForDay()：日付の時刻部分を除いて比較し、その日が予定の開始日から終了日までに含まれる予定を返します。開始日と終了日も含みます。
  • _addSchedule()：予定追加画面を開き、戻り値を受け取ったら現在のリストに加えます。

保存範囲：予定リストschedulesはこの画面State内だけにあります。SharedPreferencesなどへの保存処理がないため、この画面を破棄したりアプリを再起動したりすると、登録した予定は保持されません。

lib/screens/carender/add_schedule_screen.dart

予定名・開始日・終了日・色を入力する画面です。

  • AddScheduleScreen：カレンダー側で選択されていた日付をinitialDateとして受け取ります。
  • _AddScheduleScreenState：入力コントローラー、日付、選択色を管理します。
  • _selectStartDate() / _selectEndDate()：日付選択ダイアログを開きます。開始日が後ろへ動いた場合、終了日が前にならないよう補正します。
  • _formatDate()：日付を「年/月/日」形式で表示します。
  • _colorBox()：色選択ボタンを描画し、選択中の色に枠線を付けます。

予定名の前後の空白を除き、空欄でなければScheduleを作ってカレンダーへ返します。入力コントローラーは画面終了時に破棄します。

6. 出席管理・メモ・設定

lib/screens/otherscreen/attendance_data.dart

出席状態の種類、授業ごとの記録、集計値、端末保存をまとめます。

  • AttendanceStatus：出席（present）、欠席（absent）、遅刻（late）、公欠（excused）の4状態を定義します。
  • AttendanceStatusLabel：各状態を画面用の日本語ラベルへ変換するextensionです。
  • AttendanceStorage：SharedPreferencesのattendance_dataキーに記録をJSON保存します。
  • attendedCount：出席状態（present）の記録数を返します。
  • countedCount：公欠以外の記録数を返します。公欠は出席率の分母に入りません。
  • attendanceRate：分母が0ならnull、そうでなければ出席数÷対象記録数を返します。
  • statusFor()：日付と授業に対応する現在の状態を返します。
  • setStatus()：状態を設定・削除し、更新内容を端末に保存します。
  • _recordKey()：日付、授業名、先生、教室、開始時刻を組み合わせたキーを作ります。

lib/screens/otherscreen/attendance_screen.dart

授業ごとの出席状況を日付単位で登録する画面です。

  • AttendanceScreen / _AttendanceScreenState：選択日、読み込み中か、読み込みエラーを管理します。
  • initState() / _loadAttendance()：画面開始時に記録を読み込み、失敗時は再試行可能な案内を表示します。
  • _changeStatus()：選択した授業の状態を保存します。保存に失敗した場合はメッセージを表示します。
  • _selectDate()：今日以前の日付を選ぶ日付ピッカーを開きます。
  • _weekday()：選択日の曜日を日本語1文字に変換します。

画面は選択日と同じ曜日の時間割を表示します。各授業で出席・欠席・遅刻・公欠を選択でき、既存記録を取り消せます。日付は今日より未来へ進められません。

lib/screens/otherscreen/memoscreen.dart

MemoScreenは「メモ」という見出しと「メモ画面」という案内を表示します。メモの入力・一覧・保存機能は現時点では実装されていません。

lib/screens/class_otherscreen.dart

メインナビゲーションの「設定」タブから表示する簡易画面です。現在は設定項目を持たず、プレースホルダー表示のみです。

7. プロジェクト設定・テスト

pubspec.yaml と pubspec.lock

pubspec.yamlはアプリ名、Dart SDK条件、パッケージ依存関係を定義します。主な依存関係はFlutter本体、Flutterの日本語対応、shared_preferences（端末内保存）、table_calendar（カレンダーUI）、intl（日付・ロケール関連）です。flutter_testとflutter_lintsはテストと静的解析向けです。

pubspec.lockは実際に解決されたパッケージのバージョンを記録し、環境間で依存関係が大きく変わらないようにします。

analysis_options.yaml

Dart静的解析の設定です。flutter_lintsが提供する推奨ルールを有効にしています。解析は型や潜在的な誤り、コードスタイルなどを検出します。

test/widget_test.dart

Flutter Widget Testのサンプルです。現在のテストは、アプリを表示して「0」「1」を探すカウンターアプリ用の内容ですが、実アプリは時間割アプリであり、その画面にカウンターはありません。現在のアプリ仕様を検証するテストへ書き換える必要があります。

8. 用語集と保守上の注意点

用語意味
WidgetFlutter画面を構成する部品。テキスト、ボタン、一覧、画面全体などを表します。
State画面表示中に変化する値を保持する仕組み。例：選択タブ、選択日。
setState()Stateの値が変わったことをFlutterに知らせ、画面を再描画させます。
Navigator画面を開いたり閉じたりする仕組み。画面を閉じるときに入力結果を戻り値として渡せます。
Future / async / await端末読み込み・保存など時間のかかる非同期処理を表し、完了を待つ仕組みです。
JSONデータを文字列として表す形式。アプリのオブジェクトを端末保存向けに変換する際に使います。
SharedPreferences小規模なキー・値データを端末内に保存する仕組み。アプリを閉じた後もデータを残せます。
ControllerTextFieldの入力内容を読み書きするオブジェクト。不要になったらdispose()で解放します。

現在の実装を理解する際の注意

  1. 課題の締切：入力文字列をそのまま保存します。ホームの今日判定はYYYY-MM-DDとの完全一致、週判定は日付として解析できることが条件です。
  2. 今週の課題表示：ホームには課題名の一覧ではなく、提出済み件数／対象件数とパーセントが表示されます。
  3. カレンダー予定：予定は画面State内にしかなく、端末保存されていません。
  4. 授業時間の入力：追加・編集画面は時間を数値に変換します。例のように時と分をコロンで区切る形式が必要です。入力形式が不正な場合の包括的な入力検証はありません。
  5. メモと設定：どちらも現状はプレースホルダーで、実データを扱う機能はまだありません。
  6. テスト：同梱のWidget Testは初期テンプレートのカウンター用で、現在の主要機能を検証していません。
  7. 端末内データ：SharedPreferencesはローカル保存です。アプリのデータ消去・アンインストール・端末変更に備えるクラウド同期やバックアップ機能は見当たりません。
変更時の考え方：画面だけを変更する場合でも、登録・編集・削除の結果が一覧と保存データに反映されるか確認します。データ項目を追加・変更する場合は、Model、JSON変換、Storageの読み書き、表示画面、テストを一緒に確認します。
